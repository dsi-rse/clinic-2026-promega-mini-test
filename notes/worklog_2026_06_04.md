### 5. Conda env on cluster — home quota issue
Attempted `conda env create -f core_env.yaml` on the login node. The installation ran for a long time and eventually exhausted the home directory quota, leaving no space for anything else. Resolution:
- Moved the conda env to `/net/projects/CLS/` (project storage, not home).
- Cleaned up conda package cache (`conda clean --all`) to reclaim home space.
- Lesson learned: always install large conda envs to project storage, not home. Use `conda env create -f core_env.yaml --prefix /net/projects/CLS/<env-path>` to specify the install location upfront.

**Impact on slurm script**: `conda activate core_env` (name-based) will not find the env if it lives outside the default conda env dirs. The slurm script needs to use the full path instead:
```bash
conda activate /net/projects/CLS/<actual-env-path>
```
Update `analysis/multimodal/submit_combined.slurm` line 55 with the correct prefix path before next submission.
